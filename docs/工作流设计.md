# 工作流设计

## 应用形态

- **类型**：Dify 对话流（advanced-chat）
- **名称**：网剧自动生成
- **设计目标**：分阶段确认，质量可控、成本低、可单集修订。

## 状态机（会话变量）

| 会话变量 | 类型 | 作用 |
|---|---|---|
| `draft_outline` | string | 最近生成、待确认的大纲+人物 |
| `confirmed_outline` | string | 已确认的大纲+人物 |
| `episode_plan` | string | 分集规划（JSON，试跑时仅第 1 集） |
| `revision_note` | string | 用户最近一次修改意见 |

每轮用户消息都会执行一次完整流程，由「路由」节点根据当前状态决定走向：

```
首轮（draft/confirmed 均为空）      -> 生成大纲+人物，等待确认
已确认                             -> 单集重写 / 帮助
有大纲草稿且消息含「确认」         -> 生成分集规划+全部剧本+质检
有大纲草稿且消息含「修改」         -> 按意见修订大纲，再次等待确认
其他                              -> 帮助说明
```

## 节点图

```
start（创意/集数/字数/试跑开关）
  └→ router（代码：计算 intent / 集号 / 修改意见）
      └→ route（if-else，按 intent 分流）
          ├─ outline      → outline_gen(qwen-max) → 存 draft_outline → answer
          ├─ revise       → 存 revision_note → outline_revise(qwen-max) → 存 draft_outline → answer
          ├─ confirm      → 确认大纲 → plan_gen(qwen-max) → 存 episode_plan
          │                  → parse_plan(代码：JSON→数组)
          │                  → ep_loop(迭代 qwen-turbo 逐集生成，4 并发)
          │                  → join_scripts(代码) → video_pack(代码：提取画面提示词) → qa_gen(qwen-turbo)
          │                  → build_package(代码，含完整输出) → answer（输出剧本包）
          ├─ rewrite_ep   → rewrite_llm(qwen-turbo，按集号重写) → answer
          ├─ qa_revise    → qa_revise(LLM 按质检修订) → 提取大纲 → 更新 confirmed_outline/script_package → answer
          ├─ ep_script     → ep_script_llm(单集剧情→规范剧本) → 提取大纲 → 保存 → answer
          ├─ manga        → manga_prep(组装请求) → manga_http(HTTP 调本地编排服务)
          │                  → manga_parse(解析清单) → answer（素材清单）
          └─ help         → answer（状态说明）

确认分支：build_package → assign_package（把剧本包存入会话变量 script_package）→ manga_auto（按 start.auto_manga 分流）：
  - 是 → manga_prep → manga_http → manga_parse → answer_manga（剧本包 + 素材清单）
  - 否 → answer_final（仅剧本包）

「网剧AI漫剧生成」已并入本工作流（不再单独导入）。
```

## 输出结构（剧本包五部分）

1. **一、大纲与人物设定**：剧名/卖点/梗概/人物卡（每位角色含「定妆描述」外观锚点）/世界观/爽点节奏/前 3 集要点；随后自动附「人物定妆表」（由组装节点从人物卡提取，作为全剧固定外观锚点）
2. **二、分集规划**：每集标题与梗概（含结尾钩子）
3. **三、分集剧本**：人类阅读版，每集含场景列表（场景/人物/台词/动作/情绪/画面提示词）、结尾钩子、本集摘要
4. **四、文生视频提示词包**：由 `video_pack` 节点从剧本提取，按「集×场景」给出出场角色、画面提示词与对白/字幕，可直接提供给文生视频 AI；「出场角色」用于关联人物定妆图

剧本包确认后会存入会话变量 `script_package`；回复「生成漫剧」→ 调用本地编排服务（HTTP 节点）产出**漫剧素材清单**（每场景图片/视频 URL + 对白），供 `jimeng/assemble_manifest.py` 合成整集。
5. **五、质检报告**：一致性/钩子/字数/合规检查与修订建议

## 试跑模式

- 入参 `trial_mode=是` 时：
  - 大纲节点输出「精简版」（1 段梗概 + 人物简卡）。
  - 分集规划只生成第 1 集。
  - 迭代只跑 1 次，单集约 500-800 字。
  - 质检只检查该集钩子与敏感词。
  - 全链路 3 次短调用，目标 ≤15 秒，成本约 ¥0.1。

## 模型分配

| 节点 | 模型 | 理由 |
|---|---|---|
| outline_gen / outline_revise / plan_gen | `qwen-max` | 创意与质量把关 |
| ep_llm（迭代内）/ rewrite_llm | `qwen-turbo` | 批量、快、便宜 |
| qa_gen | `qwen-turbo` | 质检需读全剧本（131K 上下文），qwen-max 仅 32K 会超限 |

## 效率与成本策略

- 迭代节点开启 4 路并行，缩短整部生成时间。
- 试跑路径精简调用次数与输出长度。
- 确认后一次生成全集，避免重复上下文开销。
- 单集重写只重跑目标集，不整部重来。
